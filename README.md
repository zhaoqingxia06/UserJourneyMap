## 示例：听障用户的手表用户旅程

### 分析目标

梳理一位听障用户从早到晚的生活场景，寻找手表在声音提醒和语音转写方面能够发挥作用的时刻，并说明相对于手机的场景价值。

**用户画像（假设）**：30 岁二级听障上班族，有一个年幼的孩子，平时佩戴助听器，能够处理简单口语对话。生活节奏较快，兼顾工作与家庭；忙碌时担心漏听重要声音或别人的讲话，手机不在手边时尤其不踏实。

![听障用户的手表用户行为路径分析](assets/user-journey-example.png)

### 八个场景

| 场景 | 用户行为与痛点 | 用户期待与机会点 |
| --- | --- | --- |
| 清晨起床 | 睡前摘下助听器；听不到闹钟声，床头手机振动也不易察觉 | 手表到点贴腕振动，让用户独立起床 |
| 通勤买咖啡 | 店员突然问是否打包带走，没有听清；双手拿东西，不方便掏手机 | 抬腕回看刚才的话，及时回答 |
| 上午工作 | 老板交代工作，补充文档提交时间；交流突然发生，没听清截止时间 | 回看工作要求，确认时间后加入待办 |
| 中午点菜 | 店员一口气介绍几道菜，没有听全；想开启转写时对方已说完 | 回看刚才的菜名，确认后点菜 |
| 下午出差 | 拜访结束后与客户边走边聊，对方补充修改要求；部分内容没听清 | 抬腕回看客户刚才的话，确认修改内容和时间 |
| 晚上做家务 | 手机放在客厅，整理房间时没察觉门铃 | 识别门铃并腕上振动，及时去门口查看 |
| 游泳练习 | 泳池边休息时，教练纠正刚才的动作；手机放在更衣柜 | 抬腕开启转写，查看教练的纠正，再调整动作 |
| 睡前回顾 | 当天事情散落在不同交流中，细节记不清 | 查看当天摘要，确认明天需要处理的事 |

这些场景是**产品机会假设**，不是已验证的用户结论。说完后回看需要短时缓存；摘要需要相应记录能力；噪声、远距离或水边的拾音效果也需要验证。

## 使用方法

把产品目标、目标用户、已有调研和关注的问题告诉 AI，例如：

> 帮我梳理智能门锁首次安装和使用的用户旅程。先分析用户行为、痛点和手机与门锁各自能提供的帮助，确认文案后再制作旅程图。

Skill 会根据任务梳理画像与场景，区分事实与假设，检查痛点是否成立，再依据需求制作可视化或可编辑的 PPTX。
