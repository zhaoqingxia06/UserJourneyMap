# 案例与验收示例

本文件是用于学习方法的假设案例，不是调查结论或其他产品的默认设定。

## 举例：听障用户的腕上声音辅助

**产品问题**：解释语音与环境声能力放在手表上相对手机的情境价值。假设画像：30岁二级听障上班族，平时佩戴助听器，可处理简单口语交流，兼顾工作和家庭；忙时担心漏听重要信息。听力和对话能力因人而异，此处仅为讨论设定。

| 场景 | 用户行为与断点 | 机会与关键前提 |
|---|---|---|
| 起床 | 摘下助听器睡觉；手机在床头，振动未必能察觉 | 手表贴腕振动唤醒；属于闹钟基础能力，不当作语音识别能力 |
| 通勤买咖啡 | 拎着东西，店员问是否打包；漏听后不便拿手机 | 抬腕回看短句并回答；需要短时缓存 |
| 老板交代工作 | 对方补充三点前发文档，没听清截止时间 | 回看并确认，再由用户决定是否加入待办 |
| 中午点菜 | 店员一口气介绍多个菜名，用户想确认再选 | 回看店员说的菜名；插画里桌上未上菜 |
| 出差客户补充要求 | 拜访结束边走边聊，客户补充修改要求，漏听部分 | 回看短句确认内容和时间；听障能力与场景不能假设支持长时间完整口语讨论 |
| 家务等外卖 | 手机在客厅，做家务时没察觉门铃 | 识别门铃并腕上振动，提示门铃响，不直接断言外卖已到 |
| 游泳 | 在池边休息时教练纠正刚才的动作，手机在更衣柜 | 手表露出水面，开启转写查看纠正；泳池噪声、沾水拾音与湿手操作需验证 |
| 睡前 | 手机放一旁充电，想回顾当天并确认明日安排 | 查看经过授权收集的信息摘要；复杂内容可在手机查看 |

以上例子反映的是不同机制：振动触达、突发语句回看、主动开启实时转写、事后摘要。不能把它们简化成一个自动全程录音功能；不能用短回看承诺找回几分钟讨论。所有与他人交流的记录及摘要需考虑告知、选择和控制。

## 避免常见错误

- 不把熟悉路线的常规报站视为新需求，也不把手机已有屏幕信息重复包装为手表独有价值；地铁广播或异常事件需明确发生频率和是否能改变决策。
- 不把完全可通过手机轻松解决的情节改写成“只能用手表”；说明在何种条件下更方便，保留手机长文承接作用。
- 不以“误听”“忘记”为抽象痛点，要写明具体漏掉了什么及为什么当下无法及时解决。
- 避免为填满时间线强加睡前待办或长会议摘要；一个功能可能有弱价值，诚实标记。
- 不把简单故事画成复杂背景；买咖啡时用户应面向店员、尚未拿到饮品；插画和表格所示动作应一致。
- 如果用户要求所有文字可编辑，图里的气泡、屏幕文字也应单独作为可编辑文本，或透明分层覆盖并清理掉位图对应文字；检查导出，而不仅是编辑器中的外观。
